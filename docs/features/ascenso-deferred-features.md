# Ascenso features deliberately deferred

Phase 13 dispositions for items 45–55. None of these features is implemented by this phase. The current assisted product should establish pilot outcomes and renewal demand before funding generalized enterprise infrastructure.

| Item | Current capability | Why defer / exact revisit trigger |
|---|---|---|
| 45 — SAML/SSO/SCIM | Shared Google authentication, stable person ownership and scoped administrator grants. | No established directory-provisioning requirement. Revisit when a qualified buyer requires federation/provisioning or intended participants cannot use supported login. Evaluate authentication separately from Calendar. |
| 46 — Microsoft/Outlook/Teams | Google Calendar/Meet integration with manual contact/scheduling fallback. | Avoid replacing working provider integration without a blocked population. Revisit when a real program cannot participate because Google login or Calendar is unavailable; decide Entra login and Graph/Teams independently. |
| 47 — SOC 2 | Repository access controls, tests, operational history and documented recovery limits; no certification claim. | Certification cost is not validated product value. Revisit when procurement or a proposed contract specifically requires an attestation and revenue justifies an owned audit program. |
| 48 — Separate databases | Shared database, organization identity, immutable participation context and cohort grants/constraints. | Dedicated infrastructure increases migration/support burden. Revisit only for a concrete contractual isolation or residency requirement that shared controls cannot meet. |
| 49 — Generalized white-label/domains | Limited labels/sender identity, one configured public intake/origin and assisted partner-asset review. | No repeatable volume requiring a provisioning platform. Revisit after several customers need the same repeatable branded onboarding steps. |
| 50 — AI/embeddings/optimization | Deterministic exact-tag 40/35/25 scores with board-controlled selection. | No measured failure requiring another algorithm. Revisit when recorded overrides and customer outcomes identify a specific matching defect that simpler rules do not solve. |
| 51 — Public API/webhooks/Zapier/catalog | Scoped CSV exports, internal server routes and operational events. | Avoid public contracts and connector maintenance without recurring workflow demand. Revisit when a buyer identifies repeated costly manual integration work. Delivery/bounce reconciliation is the separate narrow item 17. |
| 52 — Custom BI/warehouse/prediction | Program analytics and complete named exports with documented metric limitations. | Trustworthy basic reporting and renewals come first. Revisit when customers repeatedly need cross-program analysis beyond exports; predictive engagement additionally requires validated outcomes and appropriate governance. |
| 53 — Native app/chat/video/LMS | Browser dashboards, explicit email/contact actions, Calendar/Meet and meeting/goal/survey workflows. | Extra channels create support and data-governance work. Revisit when measured participant friction shows existing channels prevent the program from working. |
| 54 — Subscription billing/provisioning | Assisted cohort setup and grants; contracts/invoicing remain operational work. | Early organization sales do not require self-service billing. Revisit at repeatable transaction volume where manual invoicing/onboarding creates material cost or errors. |
| 55 — Universal builders | Released program definition and stored survey questions; no arbitrary form/workflow engine. | Specific versioned differences are easier to validate. Revisit only when repeated paid requirements cannot be handled economically by explicit program definitions. |

Keep these decisions visible during sales. A request to reconsider a feature requires the concrete buyer/workflow, expected frequency, blocker or measurable benefit, implementation/operations owner and implications for existing records. “Enterprise products usually have it” is not sufficient evidence.
